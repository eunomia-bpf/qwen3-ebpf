An eBPF program can observe network packets before the normal socket stack, but a large language model needs matrix multiplications, attention, and a cache of earlier keys and values. A prototype can split the computation into bounded workqueue steps while keeping weights in kernel memory. The main questions are whether the verifier accepts the program, whether repeated packets preserve the correct cache state, and whether end to end latency beats a conventional user space process. A successful one token demonstration is useful, yet it cannot establish accuracy across long prompts or safe behavior under concurrent traffic. Measurements should use the same model weights, tokenization, processor affinity, and timing boundaries for both paths.
